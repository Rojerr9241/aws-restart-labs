## Objective
The goal of this lab is to architect a secure file-sharing solution using Amazon S3. You will configure an S3 bucket for an external media company, implement granular IAM permissions for a specific user (`mediacouser`), and establish an automated monitoring system using Amazon SNS to notify administrators via email whenever bucket contents are modified.

## Key Concepts

* **Amazon S3 (Simple Storage Service):** An object storage service offering industry-leading scalability, data availability, security, and performance.
* **IAM Policies (Granular Control):** Using "Prefix" (folder-level) permissions to restrict users to specific paths within a bucket.
* **Amazon SNS (Simple Notification Service):** A pub/sub messaging service. In this lab, it acts as the bridge between S3 events and the administrator's email.
* **Event Notifications:** A feature that allows S3 to publish events (Created, Removed, Restored) to targets like SNS, SQS, or Lambda.
* **AWS CLI (S3 vs S3API):** * `aws s3`: High-level commands (similar to Linux `ls`, `cp`, `sync`).
    * `aws s3api`: Low-level commands that provide access to all API operations (e.g., configuring notifications).

## Step-by-Step Instructions

### 1. Environment Setup & CLI Configuration
Connect to the CLI Host and set up the administrative environment.

1.  Connect to the **CLI Host** using EC2 Instance Connect.
2.  Configure the CLI:
    ```bash
    aws configure
    ```
    * *Access Key/Secret Key:* Use your Lab Credentials.
    * *Region:* `us-west-2` | *Format:* `json`.

### 2. S3 Bucket Provisioning
Create a unique bucket and upload initial assets.

1.  **Create Bucket:**
    ```bash
    aws s3 mb s3://cafe-[unique-name] --region us-west-2
    ```
2.  **Sync Local Images:**
    ```bash
    aws s3 sync ~/initial-images/ s3://cafe-[unique-name]/images
    ```
3.  **Verify Inventory:**
    ```bash
    aws s3 ls s3://cafe-[unique-name]/images/ --human-readable --summarize
    ```

> 📝 Technical Note: S3 Bucket Naming
> S3 bucket names are globally unique across all AWS accounts. They must be DNS-compliant: 3-63 characters, lowercase letters, numbers, and hyphens only.

### 3. Automated Notifications (SNS Setup)
Configure the alert system for the bucket.

1.  **Create SNS Topic:** Name it `s3NotificationTopic`.
2.  **Access Policy:** Edit the topic's Access Policy to allow S3 to publish messages.
3.  **Subscribe:** Add your email as a "Subscription" and **confirm** it in your inbox.

> ⚠️ Security Note: SNS Topic Policy
> By default, SNS topics don't allow other services to publish to them. You must add a "Condition" in the JSON policy to ensure only *your* specific S3 bucket (`aws:SourceArn`) can trigger emails, preventing unauthorized notification spam.

### 4. S3 Event Configuration (S3API)
Connect S3 events to the SNS topic.

1.  **Create Configuration File:** Create `s3EventNotification.json` using `vi`.
    ```json
    {
      "TopicConfigurations": [
        {
          "TopicArn": "arn:aws:sns:us-west-2:ACCOUNT-ID:s3NotificationTopic",
          "Events": ["s3:ObjectCreated:*", "s3:ObjectRemoved:*"],
          "Filter": { "Key": { "FilterRules": [{"Name": "prefix", "Value": "images/"}] } }
        }
      ]
    }
    ```
2.  **Apply Configuration:**
    ```bash
    aws s3api put-bucket-notification-configuration --bucket cafe-[unique-name] --notification-configuration file://s3EventNotification.json
    ```

### 5. Permission Testing (External User)
Switch CLI context to `mediacouser` and test operations.

1.  **Re-configure CLI:** Run `aws configure` and use the credentials of `mediacouser`.
2.  **Upload Test:**
    ```bash
    aws s3api put-object --bucket cafe-[unique-name] --key images/Caramel-Delight.jpg --body ~/new-images/Caramel-Delight.jpg
    ```
3.  **Verify Email:** Check your inbox for an "Amazon S3 Notification" with the event `ObjectCreated:Put`.
4.  **Unauthorized Test:** Attempt to change an ACL (Access Control List):
    ```bash
    aws s3api put-object-acl --bucket cafe-[unique-name] --key images/Donuts.jpg --acl public-read
    ```
    *Result:* `An error occurred (AccessDenied)`.

## Pro-Tips for Real-World Scenarios

* 💡 **Pro-Tip: S3 Versioning:** In professional media sharing, always enable **Bucket Versioning**. If an external user accidentally deletes a file, versioning allows you to recover it instantly.
* 💡 **Pro-Tip: Use S3 Lifecycle Policies:** Instead of deleting files manually, use Lifecycle Rules to move old images to **S3 Glacier Instant Retrieval** after 90 days to save up to 60-80% on storage costs.
* 💡 **Pro-Tip: S3 Block Public Access:** Unless you are hosting a public website, always keep "Block Public Access" enabled at the account level. Most data leaks in AWS happen due to misconfigured public S3 buckets.

## Useful Commands

| Command | Purpose |
| :--- | :--- |
| `aws s3 mb s3://bucket-name` | "Make Bucket": Creates a new S3 bucket. |
| `aws s3 sync [local] [s3]` | Efficiently uploads only new or changed files from local to S3. |
| `aws s3api put-bucket-notification-configuration` | Attaches a JSON event config to an existing bucket. |
| `aws sts get-caller-identity` | Verifies which IAM user (Admin vs Mediacouser) is currently active in the CLI. |

## Cleanup

1.  **Empty the Bucket:** `aws s3 rm s3://cafe-[unique-name] --recursive`. (A bucket must be empty before deletion).
2.  **Delete the Bucket:** `aws s3 rb s3://cafe-[unique-name]`.
3.  **Delete SNS Topic:** Delete `s3NotificationTopic` from the console.
