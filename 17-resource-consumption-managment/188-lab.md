# Lab 188: Managing Resources with Tagging

## Objective

To master the use of AWS resource tagging for operational automation and security compliance. You will practice using the AWS CLI and PHP SDK to discover, modify, and manage the lifecycle of EC2 instances based on their metadata.


## Key Concepts

* **Resource Tagging:** Metadata labels (key-value pairs) attached to AWS resources. They are critical for cost allocation, security policies, and automation.
* **JMESPath Querying:** A powerful query language used by the AWS CLI (`--query`) to filter and reshape JSON output directly in the terminal.
* **Batch Operations:** Performing actions (like stopping or tagging) on multiple resources at once by targeting a specific attribute rather than individual IDs.
* **Compliance Enforcement:** Using automation to identify and "punish" (stop or terminate) resources that do not follow organizational tagging standards.

## Step-by-Step Instructions

### Task 1: Using Tags to Manage Resources

In this task, you will use the AWS CLI to filter resources and update their versions.

**Step 1.1: Identify Project Instances**

Run the following command to find all instances belonging to the `ERPSystem` project:

```bash
aws ec2 describe-instances --filter "Name=tag:Project,Values=ERPSystem"
```
> 📝 Technical Note: **Server-Side Filtering** - The `--filter` parameter happens on the AWS server side. This is more efficient than downloading all data and filtering locally because it reduces the amount of data transferred over the network.

**Step 1.2: Refine Output with JMESPath**

To make the output readable, use a query to extract the Instance ID, Availability Zone, and specific Tag values:

```bash
aws ec2 describe-instances \
--filter "Name=tag:Project,Values=ERPSystem" \
--query 'Reservations[*].Instances[*].{ID:InstanceId, AZ:Placement.AvailabilityZone, Project:Tags[?Key==`Project`] | [0].Value, Environment:Tags[?Key==`Environment`] | [0].Value, Version:Tags[?Key==`Version`] | [0].Value}'
```

> **Command explanation:** The expression `Tags[?Key==Project] | [0].Value` filters the tags array for the key "Project", then pipes (`|`) that result to select only the string value.

**Step 1.3: Automate Tag Updates**

Use a Bash script to update the `Version` tag from `1.0` to `1.1` for development instances:

```bash
# Execute the provided script
./change-resource-tags.sh
```

## Pro-Tips for Real-World Scenarios
* **Standardize Tagging Policy:** Use a "Tagging Dictionary" (e.g., always use `Environment` with a capital 'E') to avoid scripts failing due to case sensitivity.

* **Use AWS Config:** Instead of manual scripts, use AWS Config Rules like `required-tags` to automatically flag or remediate non-compliant resources.

* **Infrastructure as Code (IaC):** Use Terraform or CloudFormation to ensure tags are applied at the moment of creation, rather than trying to fix them later with scripts.

* **Cost Explorer:** Use tags to generate "Cost Allocation Reports" to see exactly how much the `ERPSystem` project is costing the company each month.
