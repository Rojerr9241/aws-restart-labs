# Lab 180: Configuring an Amazon VPC

## Objective
Build a secure, scalable, and logically isolated network environment in AWS. This lab focuses on the implementation of a Multi-Tier architecture using public and private subnets, routing logic through Internet and NAT Gateways, and secure administrative access via a Bastion Host.

## Key Concepts
* **VPC (Virtual Private Cloud):** A private network "slice" in the AWS cloud (CIDR `10.0.0.0/16`).
* **Subnets:**
    * **Public:** Reachable from the internet (via Internet Gateway).
    * **Private:** Isolated from the internet (requires a NAT Gateway for outbound traffic).
* **Internet Gateway (IGW):** Allows communication between your VPC and the internet (bi-directional).
* **NAT Gateway:** Allows resources in a private subnet to connect to the internet (outbound only) while preventing the internet from initiating a connection with them.
* **Route Tables:** A set of rules (routes) that determine where network traffic is directed.
* **Bastion Host (Jump Box):** A server in the public subnet used as a secure bridge to manage instances in the private subnet.

### Task 1 to 4: Building the Infrastructure

    * **Public Route Table:** Created a route `0.0.0.0/0 -> IGW`. Associated it with the **Public Subnet**.

## 💡 Pro-Tips for Networking

1.  **Public vs. Private Logic:** An instance is "Public" ONLY if three things are true:
    - It has a Public IP.
    - Its Subnet has a route to an IGW.
    - The Network ACLs and Security Groups allow the traffic.
2.  **NAT Gateway Placement:** Always place your NAT Gateway in a **Public Subnet**. If you put it in a private subnet, it won't be able to reach the Internet Gateway to forward the traffic.
3.  **Cost Awareness:** NAT Gateways have an hourly cost and data processing charges. In smaller lab environments, people sometimes use "NAT Instances" (cheaper but manual), but NAT Gateways are the professional choice for scalability.
4.  **The 0.0.0.0/0 Route:** This is known as the "Default Route". It basically says: "If the traffic isn't for a local IP address inside this VPC, send it to this Gateway."
5.  **Security Group "Chaining":** For the Private Instance, we set the source to `10.0.0.0/16`. A more secure way is to set the source to the **Security Group ID** of the Bastion. This ensures *only* the Bastion can talk to the private instance.
