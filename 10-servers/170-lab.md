# Lab 170: Creating a Static Website on S3 using AWS CLI

## Objective
Deploy a functional static website to Amazon S3 using the AWS Command Line Interface (CLI). This lab focuses on automating resource creation, managing IAM user permissions via CLI, and developing a bash script to synchronize local changes with the cloud.

## Key Concepts
* **AWS CLI:** A unified tool to manage AWS services from the terminal.
* **S3 Static Website Hosting:** A cost-effective way to host web content without managing servers.
* **IAM Managed Policies:** Pre-built permission sets (like `AmazonS3FullAccess`) attached to users.
* **Bash Scripting:** Automating repetitive CLI commands into executable files (`.sh`).
* **S3 Sync vs CP:** Understanding the efficiency of synchronizing only modified files.

## Task 1 & 2: Environment Setup and CLI Configuration
Before interacting with AWS, the CLI must be authenticated with valid credentials.

**Instructions:**
1. Connect to the **EC2 Amazon Linux** instance via Session Manager.
2. Run `aws configure` and provide:
   - Access Key / Secret Key.
   - Region: `us-west-2`.
   - Output: `json`.

## Task 3 & 4: Resource Creation and IAM Security
Creating the bucket and a dedicated user for S3 management.

**Key Commands:**
* **Create Bucket:**
  ```bash
  aws s3api create-bucket --bucket <unique-name> --region us-west-2 --create-bucket-configuration LocationConstraint=us-west-2
  ```
* **Create IAM User:**
    ```bash
    aws iam create-user --user-name awsS3user
    ```
* **Attach Policy:**
    ```bash
    aws iam attach-user-policy --policy-arn arn:aws:iam::aws:policy/AmazonS3FullAccess --user-name awsS3user
    ```
    > 📝 Technical Note: **Policy Search** - To find specific policies via CLI, we use queries: `aws iam list-policies --query "Policies[?contains(PolicyName,'S3')]"`

## Task 5: Adjusting S3 Permissions
By default, S3 buckets are private. To host a website, we must:

1. **Disable "Block Public Access"** in the S3 Console.
2. **Enable ACLs** (Access Control Lists) to allow individual objects to be readable by the public.

---

## Task 6 & 7: Website Deployment
Uploading the static files (HTML, CSS, Images) to the bucket.

**Commands**:

* **Enable Hosting**:
    ```bash
    aws s3 website s3://<my-bucket>/ --index-document index.html
    ```
* **Upload Content**:
    ```bash
    aws s3 cp ./static-website/ s3://<my-bucket>/ --recursive --acl public-read
    ```

## Task 8: Automation and Repeatability (The Script)
To avoid typing long commands every time the website changes, we create an automation script.

Script Content (`update-website.sh`):
    ```bash
    #!/bin/bash
    aws s3 cp /home/ec2-user/sysops-activity-files/static-website/ s3://<my-bucket>/ --recursive --acl public-read
    ```
> 💡 Pro-Tip: `Efficiency with s3 sync` - The `cp` command uploads everything every time. In a real-world scenario with thousands of images, this is inefficient. Using `aws s3 sync` is better because it compares the local source and the S3 destination, uploading only the files that have changed.

**Optimized Command**:
    ```bash
    aws s3 sync ./static-website/ s3://<my-bucket>/ --acl public-read
    ```

## Command Reference Summary

| Component | Action |
| :--- | :--- |
| `aws configure` | Set up security credentials and region. |
| `aws s3api create-bucket` | Create a new S3 bucket (Low-level API). |
| `aws iam create-user` | Create a new identity in the account. |
| `aws s3 cp --recursive` | Copy a whole directory to S3. |
| `aws s3 sync` | Sync directories (incremental updates). |
| `chmod +x script.sh` | Grant execution permissions to a bash file. |
