# Lab 168: Install and Configure the AWS CLI
**Course:** AWS re/Start | **Module:** SysOps / System Operations

## Objective
The goal of this lab is to move beyond the AWS Management Console and learn how to manage cloud resources via the command line. You will install the AWS CLI v2 on a Red Hat Enterprise Linux (RHEL) instance, configure it with programmatic access keys, and interact with the Identity and Access Management (IAM) service to retrieve policy data.

## Key Concepts

* **AWS CLI (Command Line Interface):** A unified tool to manage AWS services. It allows for automation through scripts (Bash, Python) and faster resource management.
* **Programmatic Access:** Access to AWS resources via API calls. Unlike the Console (Username/Password), the CLI requires an **Access Key ID** and a **Secret Access Key**.
* **JSON (JavaScript Object Notation):** The standard text-based format for representing structured data. It is the default output format for the AWS CLI.
* **IAM Policies:** Documents that define permissions. Using the CLI, you can audit these policies to ensure the Principle of Least Privilege is followed.

## Step-by-Step Instructions

### 1. Connection to Red Hat Instance
Access the RHEL environment via SSH. 

```bash
# Set permissions for your private key
chmod 400 labsuser.pem

# Connect to the instance
ssh -i labsuser.pem ec2-user@<public-ip>
```
### 2. AWS CLI v2 Installation
Unlike Amazon Linux, RHEL requires a manual installation of the CLI binaries.

1.  **Download the installer package:**
    ```bash
    curl "[https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip](https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip)" -o "awscliv2.zip"
    ```
    > **Command explanation:** `curl` is used to download the installation file directly from AWS servers. The `-o` flag specifies the output filename as `awscliv2.zip`.

2.  **Extract the files:**
    ```bash
    unzip -u awscliv2.zip
    ```
    > **Command explanation:** The `unzip` command extracts the contents of the compressed package. The `-u` (update) flag ensures that existing files are overwritten or updated without repetitive prompts.

3.  **Execute the install script:**
    ```bash
    sudo ./aws/install
    ```
    > **Command explanation:** This runs the official installation script located in the extracted `aws` folder. `sudo` is required because the installer writes files to system directories like `/usr/local/aws-cli`.

4.  **Verify the installation:**
    ```bash
    aws --version
    ```

> 📝 Technical Note: CLI v2 Features
> AWS CLI v2 is the most recent version and offers significant improvements over v1, including better interactive features, pre-packaged installers for all operating systems, and a more robust auto-completion engine.

### 3. Programmatic Configuration
Bridge the gap between your terminal and the AWS Cloud by establishing your security credentials.

1.  **Initiate the configuration wizard:**
    ```bash
    aws configure
    ```
    > **Command explanation:** `aws configure` is the primary interactive way to set up your AWS CLI installation. It creates two files in the `~/.aws` directory: `config` (settings) and `credentials` (sensitive keys).

2.  **Provide the following parameters when prompted:**
    * **AWS Access Key ID:** `[Your_Access_Key_ID]`
    * **AWS Secret Access Key:** `[Your_Secret_Access_Key]`
    * **Default region name:** `us-west-2`
    * **Default output format:** `json`

> 📝 Technical Note: Default Output Formats
> While `json` is the standard for automation and scripts, the AWS CLI also supports `table` (highly readable for humans) and `text` (useful for simple bash processing using `grep` or `awk`).

> ⚠️ Security Note: Static Credentials Risk
> In professional production environments, storing static Access Keys on an EC2 instance is a security risk. The industry best practice is to use **IAM Roles** (Instance Profiles), which allow the CLI to securely retrieve temporary, rotating credentials without storing sensitive keys on the disk.

### 4. Auditing IAM via Command Line
Validate the connection and perform security audits on the account's identity configuration.

1.  **List all IAM users:**
    ```bash
    aws iam list-users
    ```
    > **Command explanation:** This calls the IAM service API to retrieve a list of all users. It confirms that your credentials have the necessary permissions to read identity data.

2.  **Challenge: Retrieve the JSON Policy Document:**
    * **Find the Policy ARN:**
        ```bash
        aws iam list-policies --scope Local
        ```
    * **Export the Policy Version to a file:**
        ```bash
        aws iam get-policy-version --policy-arn <YOUR_POLICY_ARN> --version-id v1 > lab_policy.json
        ```
    > **Command explanation:** The `>` operator is a shell redirection that captures the JSON output from the AWS API and saves it into a local file named `lab_policy.json`.

## Pro-Tips for Real-World Scenarios

* 💡 **Pro-Tip: Leverage IAM Roles for EC2:** Never run `aws configure` on a production EC2 instance. Instead, attach an **IAM Role** to the instance. The CLI will automatically use temporary credentials, which is significantly more secure as it leaves no sensitive keys on the disk.
* 💡 **Pro-Tip: Use --query for Efficiency:** AWS responses can be huge. Use the `--query` parameter (based on JMESPath) to extract only what you need. Example: `aws iam list-users --query 'Users[*].UserName'` returns a simple list of names without the surrounding metadata.
* 💡 **Pro-Tip: Named Profiles:** If you work with multiple AWS accounts (e.g., Dev, Test, Prod), use the `--profile` flag. Run `aws configure --profile production` to keep credentials separate and avoid accidental deployments to the wrong environment.

## Useful Commands

| Command | Purpose |
| :--- | :--- |
| `aws sts get-caller-identity` | The "Who Am I" of AWS. Verifies which user/role and account you are currently using. |
| `aws configure list` | Displays the current active configuration, including the region and where credentials are being sourced from. |
| `aws iam list-policies --scope Local` | Filters for "Customer Managed" policies, ignoring the hundreds of default AWS managed policies. |
| `aws help` | Opens the built-in documentation directly in the terminal for any service or command. |
| `cat lab_policy.json` | Displays the content of your exported JSON policy in the terminal for quick review. |
