# Lab 263: Creating Subnets and IP Allocation in a VPC ✅

## Objective
Design and implement a custom Virtual Private Cloud (VPC) based on specific startup requirements. This involves selecting appropriate CIDR blocks to accommodate a large number of internal hosts while ensuring a smaller, functional public subnet for operational needs.

## Key Concepts
* **RFC 1918:** The international standard that defines private IP address ranges (10.x.x.x, 172.16.x.x, and 192.168.x.x) which are not routable on the public internet.
* **CIDR Notation:** A method for allocating IP addresses and IP routing (e.g., `/16` provides 65,536 addresses, while `/24` provides 256).
* **VPC Wizard:** An AWS tool that automates the creation of a VPC along with its essential components like subnets, route tables, and Internet Gateways.
* **Subnetting:** The practice of dividing a large network into smaller, manageable segments.

## Task 1: Investigation and VPC Architecture
The customer, Paulo, required a specific setup:
1. **Total Capacity:** ~15,000 private IP addresses.
2. **Private Range:** Must start with `192.x.x.x`.
3. **Public Subnet:** Needs at least 50 available IP addresses.

### 1. Determining the CIDR Blocks
To meet the requirement of 15,000 IPs using a 192.168 range:
* **VPC CIDR:** `192.168.0.0/18` was selected. 
    * *Why?* A `/18` mask provides **16,384** total IP addresses, which is the closest power of 2 that covers the requested 15,000.
* **Public Subnet CIDR:** `192.168.1.0/26` was selected.
    * *Why?* A `/26` mask provides **64** total IP addresses, which comfortably covers the requested 50 IPs.

### 2. Launching the VPC
Using the **VPC Wizard** with the "VPC with a Single Public Subnet" configuration:
* **Name:** `First VPC`
* **IPv4 CIDR block:** `192.168.0.0/18`
* **Public subnet's IPv4 CIDR:** `192.168.1.0/26`
* **Internet Gateway:** Automatically created and attached to allow the Public Subnet to communicate with the internet.
* **Availability Zone:** Set to "No Preference" to let AWS choose the best physical location.

## 💡 Pro-Tips for VPC Design

1. **The AWS "Reserved" IPs:** Note that for every subnet you create, AWS reserves **5 IP addresses** for internal networking purposes (Network address, VPC Router, DNS, Future use, and Broadcast). Always account for this when calculating your requirements!
2. **Plan for Growth:** It is always better to choose a slightly larger CIDR block than you currently need. Changing a VPC's primary CIDR after resources are launched is a complex process.
3. **Public vs. Private:**
   - **Public Subnet:** Has a direct route to an Internet Gateway (IGW).
   - **Private Subnet:** Does not have a route to an IGW. To access the internet, it needs a NAT Gateway.
4. **IP Calculators:** Tools like `subnet-calculator.com` are essential for junior and senior engineers alike to avoid manual math errors during the design phase.
