## Objective
The goal of this lab is to architect a custom, routable network environment within AWS. You will resolve a startup's connectivity issues by manually building a Virtual Private Cloud (VPC), configuring public subnets, establishing internet access via an Internet Gateway (IGW), and implementing a dual-layer security strategy using Network ACLs and Security Groups.

## Key Concepts

* **VPC (Virtual Private Cloud):** A logically isolated virtual network in the AWS cloud. You have full control over IP address ranges, subnets, and routing.
* **Internet Gateway (IGW):** A redundant, highly available VPC component that allows communication between your VPC and the internet. It performs Network Address Translation (NAT) for instances with public IPs.
* **Subnets:** Segments of a VPC's IP address range. Public subnets have a route to an IGW; private subnets do not.
* **Route Tables:** A set of rules (routes) that determine where network traffic from your subnets or gateways is directed.
* **Stateful vs. Stateless Firewalls:**
    * **Security Groups (Stateful):** If you allow an inbound request, the response is automatically allowed, regardless of outbound rules.
    * **NACLs (Stateless):** Return traffic must be explicitly allowed by an outbound rule.

> 📝 Technical Note: CIDR and AWS Reserved IPs
> A /24 subnet mask provides 256 IP addresses. However, AWS reserves 5 IP addresses in each subnet:
> 1. 10.0.x.0: Network address.
> 2. 10.0.x.1: VPC router.
> 3. 10.0.x.2: DNS mapping.
> 4. 10.0.x.3: Future use.
> 5. 10.0.x.255: Network broadcast.

### 2. Enabling Internet Egress
Create an Internet Gateway and link it to your VPC.

1.  Create the **Internet Gateway** named `Test IGW`.
2.  Select `Test IGW` -> **Actions** -> **Attach to VPC** -> Select `Test VPC`.
3.  **Route Table Setup:**
    * Create a route table named `Public Route Table`.
    * **Edit Routes:** Add a route with Destination `0.0.0.0/0` and Target `Internet Gateway` (`Test IGW`).
    * **Subnet Associations:** Associate the `Public Subnet` with this route table.

> **Command explanation:** `0.0.0.0/0` represents the "Default Route". It tells the VPC that any traffic not meant for the local network should be sent to the Internet Gateway.

### 3. Layered Security Configuration
Configure both the NACL (Subnet level) and Security Group (Instance level).

* **Network ACL (Public Subnet NACL):**
    * **Inbound Rules:** Rule #100 | All Traffic | 0.0.0.0/0 | ALLOW.
    * **Outbound Rules:** Rule #100 | All Traffic | 0.0.0.0/0 | ALLOW.
* **Security Group (Public Security Group):**
    * **Inbound:**
        * SSH (Port 22) | Source: `0.0.0.0/0`
        * HTTP (Port 80) | Source: `0.0.0.0/0`
        * All ICMP - IPv4 (Required for Ping) | Source: `0.0.0.0/0`

> ⚠️ Security Note: SSH Exposure
> Opening port 22 to `0.0.0.0/0` is a high security risk. In real-world scenarios, always restrict SSH access to your specific Public IP (My IP) or use AWS Systems Manager Session Manager to connect without opening inbound ports.

## Pro-Tips for Real-World Scenarios

* 💡 **Pro-Tip: Use NAT Gateways for Private Subnets:** In a production environment, database servers should be in a **Private Subnet**. To allow them to download updates without being exposed to the internet, use a **NAT Gateway** in the Public Subnet instead of an IGW.
* 💡 **Pro-Tip: Naming Conventions:** Instead of "Test VPC", use structured names like `proj-prod-useast1-vpc`. This is crucial for automation and infrastructure as code (Terraform/CloudFormation).
* 💡 **Pro-Tip: Ephemeral Ports:** Remember that NACLs are stateless. If you restrict outbound traffic in a NACL, you must allow return traffic on **Ephemeral Ports** (typically 1024-65535) for your connections to work.
