# Lab 262: Static and Dynamic IP Addresses ✅

## Objective
Investigate and resolve a common cloud infrastructure issue: changing public IP addresses upon instance restart. The goal is to understand the behavior of dynamic IP allocation in AWS and implement a persistent solution using Elastic IPs (EIP).

## Key Concepts
* **Dynamic Public IP:** A public IP address assigned by AWS from its pool that is released when an instance is stopped or terminated.
* **Static IP (Elastic IP):** A reserved public IP address that remains associated with your AWS account and can be mapped to any instance, providing a persistent entry point.
* **Private IP:** An internal address that stays the same throughout the lifecycle of the instance (even through stops/starts), used for communication within the VPC.

## Task 1: Investigation and Problem Replication
The customer, Bob, reported that his instance's IP changes every time he restarts it to save costs, breaking his external configurations.

### The Dynamic Behavior
* **Initial State:** Instance Running -> Public IP: `X.X.X.X`
* **After Stop/Start:** Instance Running -> Public IP: `Y.Y.Y.Y`
* **Conclusion:** Standard Public IPs are **dynamic**. They are tied to the "running" state of the virtual hardware. When Bob stops the instance, AWS reclaims the IP.

## 2. Testing the Dynamic Behavior
Once the instance state reached **2/2 checks passed**, we performed a state-change test:

* **Initial State:** Instance **Running**. We noted the **Public IPv4 address** (e.g., `54.120.x.x`).
* **Action:** Selected **Instance state > Stop instance**.
* **Observation:** Once stopped, the Public IP address **disappeared** from the Networking tab.
* **Restart:** Selected **Instance state > Start instance**.
* **Result:** A **new** Public IPv4 address was assigned (e.g., `34.201.x.x`).

> **Conclusion:** Standard Public IPs are **dynamic**. AWS reclaims these IPs when an instance stops to optimize their IPv4 pool. This confirms we have successfully replicated Bob's issue.

## 3. Implementing the Solution: Elastic IP (EIP)
To provide Bob with a permanent, static address, we implemented an **Elastic IP**.

### Workflow:
1. **Allocation:** Reserved a static address from the AWS pool via **Network & Security > Elastic IPs**.
2. **Association:** Linked the EIP to the specific `test instance`.
3. **Verification:**
   - **Stop Instance:** The Public IP (EIP) remains assigned in the console.
   - **Start Instance:** The Public IP (EIP) remains exactly the same as before.
   - **Result:** The connection is now **static** and persistent.

### Step 1: Allocation
1.  In the left navigation pane, under **Network & Security**, selected **Elastic IPs**.
2.  Clicked **Allocate Elastic IP address**.
3.  Left settings as default (Amazon's pool of IPv4 addresses) and clicked **Allocate**.
4.  A static IP was reserved for our account.

### Step 2: Association
1.  Selected the newly created EIP from the list.
2.  Clicked **Actions > Associate Elastic IP address**.
3.  **Resource type:** Kept as `Instance`.
4.  **Instance:** Selected `test instance` from the dropdown.
5.  **Private IP address:** Selected the private IP associated with the instance.
6.  Clicked **Associate**.

### Step 3. Final Verification
We returned to the **Networking** tab of the `test instance`:
* **Observed:** The "Public IPv4 address" now matches our **Elastic IP**.
* **The "Stop/Start" Test:** We stopped the instance again.
* **Result:** Unlike the first test, the **Elastic IP address remained assigned** to the instance even while stopped. Upon starting, the IP remained identical.

**Final Result:** The connection is now **static and persistent**. Bob can now restart his instance as needed without breaking his external configurations.

## 💡 Pro-Tips for IP Management

1. **EIP Costs:** AWS provides one Elastic IP at no cost while it is associated with a **running** instance. However, to prevent IP waste, AWS charges a small hourly fee if the EIP is unassociated or if the instance it's attached to is **stopped**.
2. **Private IP Stability:** Unlike public IPs, the **Private IP** of an instance never changes unless the instance is terminated. For internal communication between servers, always use the Private IP.
3. **Release your EIPs:** When you no longer need a static IP, you must both **disassociate** it from the instance and **release** it back to AWS to stop incurring charges.
4. **DNS over IPs:** In production, it is often better to use a DNS name (Route 53) pointing to the EIP or a Load Balancer, providing an extra layer of abstraction.
