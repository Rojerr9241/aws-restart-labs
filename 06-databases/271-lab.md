# Lab 271: Performing a Conditional Search

## Objective
Refine data retrieval techniques by using advanced filtering in the `WHERE` clause. This lab focuses on range-based searches (`BETWEEN`), pattern matching (`LIKE`), result aggregation (`SUM`), and handling case sensitivity using built-in functions.

## Key Concepts
* **Range Filtering (`BETWEEN`):** A cleaner way to filter values within a specific range (inclusive).
* **Pattern Matching (`LIKE`):** Used with wildcards (`%`) to search for partial text matches.
* **Aggregations (`SUM`):** Mathematical functions that calculate the total of a numeric column across multiple rows.
* **Aliasing (`AS`):** Assigning user-friendly names to result columns, especially useful for calculated values.
* **String Normalization (`LOWER`):** Converting text to lowercase to ensure searches are successful regardless of the database's case-sensitivity settings.

Task 2: Advanced Querying Techniques
1. Range Conditions: Operators vs. BETWEEN
We compared two ways of finding countries with populations between 50M and 100M:

* The Logic Way: `WHERE Population >= 50000000 AND Population <= 100000000`
* The Clean Way: `WHERE Population BETWEEN 50000000 AND 100000000`
Note: `BETWEEN` is inclusive, meaning it counts the exact start and end values.

2. Wildcards and Pattern Matching
To find any region containing the word "Europe" (like "Southern Europe" or "Western Europe"), we used the `%` wildcard:

```SQL
-- The % symbol represents any number of characters
SELECT sum(Population) AS "Europe Total" 
FROM world.country 
WHERE Region LIKE "%Europe%";
```

3. Handling Case Sensitivity
To avoid issues where "Central" might be stored as "central", we used the `LOWER()` function to normalize the search:

```SQL
SELECT Name, Region 
FROM world.country 
WHERE LOWER(Region) LIKE "%central%";
```

### 💡 Challenge: North America Summary
Question: Return the sum of the Surface Area and Population for North America.

**The Solution:**
```SQL
SELECT SUM(SurfaceArea) AS "N. America Surface Area", 
       SUM(Population) AS "N. America Population" 
FROM world.country 
WHERE Region = "North America";
```

## 💡 Pro-Tips for Conditional Searches

1. **Wildcard Strategy:**
   - `LIKE 'North%'`: Finds strings *starting* with North.
   - `LIKE '%America'`: Finds strings *ending* with America.
   - `LIKE '%central%'`: Finds strings containing "central" *anywhere*.
2. **Aggregates vs. Row Data:** When using functions like `SUM()`, the database collapses multiple rows into a single result. You cannot display individual names and a total sum in the same simple row without using more advanced clauses like `GROUP BY`.
3. **The Cleanliness of BETWEEN:** Use `BETWEEN` instead of `>= AND <=` to make your code more readable for other developers. It works perfectly for numbers, dates, and even alphabetical ranges.
4. **Professional Aliasing:** Always use the `AS` operator when performing calculations. A header like `"Total Population"` is much more professional and easier for a business user to understand than `sum(population)`.
5. **Data Sensitivity:** While SQL keywords (like `SELECT`) are case-insensitive, the **values** stored in the database might not be. Using `LOWER(ColumnName)` in your `WHERE` clause is a "bulletproof" way to ensure your search finds 'Central', 'central', and 'CENTRAL' all at once.

| `SUM()` | An aggregate function that calculates the total of a numeric column. |
| `AS` | Assigns a temporary alias to a column for the result set. |

| `AND` | Combines multiple conditions; all must be true for a row to show. |
