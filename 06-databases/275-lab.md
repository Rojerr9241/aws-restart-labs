## Objective
The goal of this lab is to explore the fundamental operations of Amazon DynamoDB, a serverless NoSQL database. You will learn how to design a table with a composite primary key, manage schema-less data (items and attributes), and understand the performance differences between Query and Scan operations.

## Key Concepts

* **NoSQL Database:** A non-relational database that allows for flexible schemas, making it ideal for rapid development and massive horizontal scaling.
* **Partition Key (PK):** Also known as a Hash Key, it is used to distribute data across multiple partitions for scalability.
* **Sort Key (SK):** Also known as a Range Key, it allows you to store multiple items with the same Partition Key in a sorted order.
* **Composite Primary Key:** The combination of a Partition Key and a Sort Key (`Artist` + `Song` in this lab).
* **Items & Attributes:** An "Item" is a row, and an "Attribute" is a column. Unlike SQL, items in the same table can have different attributes.
* **Query vs. Scan:**
    * **Query:** Efficiently finds items using only the Primary Key. It is fast and cost-effective.
    * **Scan:** Examines every single item in the table. It is slow and expensive for large datasets.

## Step-by-Step Instructions

### 1. Table Provisioning
Create the data structure for the music library.

* **Table Name:** `Music`
* **Partition Key:** `Artist` (String)
* **Sort Key:** `Song` (String)
* **Settings:** Default (Provisioned capacity).

> 📝 Technical Note: Partition Key Selection
> Choosing a high-cardinality Partition Key (one with many unique values) is a Best Practice to avoid "Hot Partitions," which can bottleneck your database performance.

### 2. Populating Schema-less Data
DynamoDB allows each item to have unique attributes without pre-defining them in the table settings.

1.  **Item 1:** Artist: `Pink Floyd` | Song: `Money` | Album: `The Dark Side of the Moon` | Year: `1973`.
2.  **Item 2:** Artist: `John Lennon` | Song: `Imagine` | Genre: `Soft rock` (Note the unique 'Genre' attribute).
3.  **Item 3:** Artist: `Psy` | Song: `Gangnam Style` | LengthSeconds: `219`.

> 📝 Technical Note: DynamoDB Data Types
> DynamoDB supports various types: **S** (String), **N** (Number), **B** (Binary), **BOOL** (Boolean), and complex types like **M** (Map) or **L** (List) for JSON-like structures.

### 3. Data Manipulation and Retrieval
Correcting errors and exploring the data.

* **Update Item:** Find the item for `Psy`, and update the `Year` attribute from `2011` to `2012`.
* **The Query Operation:**
    * Search by `Artist = Psy`.
    * This is an indexed lookup; DynamoDB goes directly to the partition where the data lives.
* **The Scan Operation:**
    * Apply a filter: `Year = 1971`.
    * This forces DynamoDB to read every item in the table before applying the filter.

> **Command explanation:** In DynamoDB, a **Filter Expression** in a Scan does NOT reduce the cost. You are charged for reading the entire table, and then DynamoDB hides the results that don't match your filter.

## Pro-Tips for Real-World Scenarios

* 💡 **Pro-Tip: Avoid Scans in Production:** Scans consume Read Capacity Units (RCUs) for every item in the table. As your table grows to millions of rows, a Scan can become extremely slow and expensive. Always try to model your data to use **Queries**.
* 💡 **Pro-Tip: Use Global Secondary Indexes (GSI):** If you need to search by an attribute that isn't the Primary Key (e.g., searching by `Year`), create a GSI. This creates a "shadow copy" of your table with a different Partition Key to allow fast Queries.
* 💡 **Pro-Tip: TTL (Time to Live):** You can set a TTL attribute to automatically delete old items (like session logs or temporary cart data) at no extra cost, helping you manage storage and compliance.

## Useful Commands (AWS CLI)

If you were to perform these tasks via terminal, you would use these commands:

| Command | Purpose |
| :--- | :--- |
| `aws dynamodb put-item` | Creates a new item in the table. |
| `aws dynamodb get-item` | Retrieves a specific item using the Primary Key. |
| `aws dynamodb query` | Finds items based on the Partition Key (High performance). |
| `aws dynamodb scan` | Reads every item in the table (Low performance). |
