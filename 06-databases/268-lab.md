# Lab 268: Database Table Operations

## Objective
Learn and practice fundamental Data Definition Language (DDL) operations in a MySQL environment. This includes creating databases and tables, inspecting structures, altering schemas, and safely removing resources.

## Key Concepts
* **DDL (Data Definition Language):** SQL statements like `CREATE`, `ALTER`, and `DROP` that define the database structure.
* **Command Host:** An EC2 instance acting as a client to interact with the database engine.
* **Schema:** The formal structure of a table, defining column names, data types (INT, CHAR, FLOAT), and constraints (NOT NULL, PRIMARY KEY).

## Task 2: Data Definition Operations

In this phase, we create the logical containers for our data.

**Creating and Inspecting**
1. Create Database: `CREATE DATABASE world;`

2. Verify: `SHOW DATABASES;`

3. Create Table: A complex `CREATE TABLE` statement was used to define the `country` table, including data types like `ENUM` for continents and a `PRIMARY KEY` for the unique country code.

**Altering the Schema**
During inspection, a typo was found in the column Conitinent.

- **Action**: Rename the column to fix the error.
- **Command**:
    ```SQL
    ALTER TABLE world.country RENAME COLUMN Conitinent TO Continent;
    ```
  > 📝 Technical Note: `SHOW COLUMNS`. This command is essential for developers to verify that the data types and nullability constraints match the application requirements.

## Challenge 1: Creating a New Table
**Requirement**: Create a `city` table with `Name` and `Region` columns.
**Solution**:
    ```SQL
    CREATE TABLE world.city (`Name` CHAR(52), `Region` CHAR(26));
    ```

---

## Task 3: Deleting Databases and Tables
The `DROP` statement is irreversible. It removes both the structure and all contained data.

**Commands**:
1. Drop Table: `DROP TABLE world.city;`
2. Drop Database: `DROP DATABASE world;`

>💡 Pro-Tip: In production environments, **never** run a `DROP` command without a recent snapshot or backup. AWS services like **Amazon RDS** offer "Deletion Protection" to prevent accidental data loss from these specific SQL commands.
