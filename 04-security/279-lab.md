# Lab 279: Introduction to AWS Identity and Access Management (IAM)

## Objective
Master the fundamentals of access control by managing users, groups, and policies. Learn to enforce security best practices through password policies and test granular permissions for different administrative roles.

## Key Concepts
* **IAM User:** An entity that represents a person or service to interact with AWS.
* **IAM Group:** A collection of IAM users. Permissions granted to a group are inherited by all users within it.
* **Policy:** A JSON document that defines permissions (What can they do? On which resource?).
* **Managed Policy:** A standalone policy managed by AWS (e.g., `AmazonS3ReadOnlyAccess`).
* **Inline Policy:** A policy embedded directly into a single user or group.

> ### 📝 Technical Note: JSON Policy Structure
> Every IAM policy follows a standard structure:
> - **Effect:** `Allow` or `Deny`.
> - **Action:** The specific API calls (e.g., `ec2:StartInstances`).
> - **Resource:** The ARN (Amazon Resource Name) of the assets affected. Use `*` for all resources.
