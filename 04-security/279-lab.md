## Objective

## Key Concepts
* **IAM User:** An entity that represents a person or service to interact with AWS (e.g., `user-1`).
* **IAM Group:** A collection of IAM users. Permissions granted to a group are inherited by all users within it.
* **Policy:** A JSON document that defines permissions (Allow/Deny) for specific actions on specific resources. (What can they do? On which resource?).
* **Managed vs. Inline Policies:**
    - **Managed:** Pre-built by AWS (e.g., `AmazonS3ReadOnlyAccess`).
    - **Inline:** Custom-built for a specific user or group (e.g., `EC2-Admin-Policy`).
* **Least Privilege:** Giving users only the exact permissions they need to perform their jobs, and nothing more.

> ### 📝 Technical Note: Inline Policies
> Unlike the other groups that use AWS Managed Policies, the `EC2-Admin` group has a **Customer inline policy**. 
> * **Definition:** An inline policy is a policy assigned to only one specific user or group. 
> * **Use Case:** They are typically used for "one-off" situations where you don't want the policy to be available for reuse elsewhere in the account.

**JSON Policy Structure Recap:**
Every IAM policy follows a standard structure:
- **Effect:** `Allow` or `Deny`.
- **Action:** Specific API calls (e.g., `ec2:StartInstances`).
- **Resource:** The ARN (Amazon Resource Name) of the assets affected. Use `*` for all resources.

## 💡 Pro-Tips for Identity Management

1. **Groups over Users:** Never attach policies directly to a user. Always use groups. If a person changes roles, you simply move them to a different group, and their permissions update instantly.
2. **The Power of Deny:** In AWS, an explicit **Deny** always overrides an **Allow**. If a user belongs to a group that allows EC2 and another that denies it, the user will be denied.
3. **JSON Policy Structure:** Every policy statement has four main elements (PARC):
    - **P**rincipal: Who is affected.
    - **A**ction: What they can do (e.g., `s3:Get*`).
    - **R**esource: Which specific object (e.g., a specific bucket or `*` for all).
    - **C**ondition: When it applies (e.g., only if MFA is active).
4. **IAM Sign-in URL:** You can customize the account alias (e.g., `https://my-company.signin.aws...`) in the IAM Dashboard to make it easier for employees to remember.
