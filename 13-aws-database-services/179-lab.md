# Lab: Migrating to Amazon RDS
**Course:** AWS re/Start | **Module:** AWS Database Services

## Objective
The goal of this lab is to migrate a production MariaDB database from an EC2 instance (LAMP stack) to a fully managed Amazon RDS instance. You will practice creating cloud infrastructure via the AWS CLI, performing a database migration using the `mysqldump` utility, and reconfiguring a live application using AWS Systems Manager Parameter Store.

## Key Concepts

* **Amazon RDS (MariaDB):** A managed relational database service that automates hardware provisioning, database setup, patching, and backups.
* **Database Migration (mysqldump):** A logical backup utility that produces a set of SQL statements that can be executed to reproduce the original database object definitions and table data.
* **Parameter Store (AWS Systems Manager):** A capability that provides secure, hierarchical storage for configuration data and secrets. It allows decoupling configuration from the application code.
* **DB Subnet Group:** A collection of subnets (typically private) that you designate for your RDS DB instances in a VPC, requiring at least two subnets in different Availability Zones for high availability.

## Step-by-Step Instructions

### 1. Data Generation (Pre-Migration)
Ensure there is existing data in the local database to verify a successful migration later.

1.  Access the **CafeInstanceURL**.
2.  Place several orders in the **Menu** section.
3.  Check **Order History** and note the total number of orders.

### 2. Provisioning Infrastructure via AWS CLI
Connect to the **CLI Host** and build the destination environment.

1.  **Configure CLI:** `aws configure` (Use Lab credentials, Region: `us-west-2`).
2.  **Create Security Group:**
    ```bash
    aws ec2 create-security-group --group-name CafeDatabaseSG --description "Security group for Cafe database" --vpc-id <CafeVpcID>
    ```
3.  **Authorize Inbound Traffic:**
    ```bash
    aws ec2 authorize-security-group-ingress --group-id <CafeDatabaseSG_ID> --protocol tcp --port 3306 --source-group <CafeSecurityGroupID>
    ```
4.  **Create Private Subnets:**
    * **Subnet 1:** CIDR `10.200.2.0/23` (Same AZ as CafeInstance).
    * **Subnet 2:** CIDR `10.200.10.0/23` (Different AZ).
5.  **Create DB Subnet Group:**
    ```bash
    aws rds create-db-subnet-group --db-subnet-group-name "CafeDB Subnet Group" --db-subnet-group-description "DB subnet group for Cafe" --subnet-ids <Subnet1_ID> <Subnet2_ID>
    ```

### 3. Launching the RDS Instance
Deploy the managed MariaDB engine.

```bash
aws rds create-db-instance \
--db-instance-identifier CafeDBInstance \
--engine mariadb \
--engine-version 10.5.13 \
--db-instance-class db.t3.micro \
--allocated-storage 20 \
--availability-zone <AZ_of_CafeInstance> \
--db-subnet-group-name "CafeDB Subnet Group" \
--vpc-security-group-ids <CafeDatabaseSG_ID> \
--no-publicly-accessible \
--master-username root --master-user-password 'Re:Start!9'
```
> 📝 Technical Note: Public Accessibility - Setting `--no-publicly-accessible` ensures the database is only reachable from within the VPC, significantly reducing the attack surface.

### 4. Database Migration (The "Lift & Shift")
Execute the transfer of data from the local MariaDB process to the managed RDS instance.

1.  **Export Local Data:**
    Connect to the `CafeInstance` and create a logical backup:
    ```bash
    mysqldump --user=root --password='Re:Start!9' --databases cafe_db --add-drop-database > cafedb-backup.sql
    ```
    > **Command explanation:** `mysqldump` captures the entire structure (DDL) and data (DML) of the `cafe_db`. The `--add-drop-database` flag ensures that the target RDS instance will overwrite any existing database with the same name during import.

2.  **Import to RDS:**
    ```bash
    mysql --user=root --password='Re:Start!9' --host=<RDS_Endpoint_Address> < cafedb-backup.sql
    ```
    > **Command explanation:** This command pushes the SQL script generated in the previous step into the remote RDS instance. The `<` operator acts as an input redirector.

3.  **Verify Migration:**
    Log in to the RDS instance and check the data:
    ```bash
    mysql --user=root --password='Re:Start!9' --host=<RDS_Endpoint_Address> cafe_db
    # Inside the MySQL shell:
    SELECT * FROM product;
    EXIT;
    ```

### 5. Application Reconfiguration
Update the application's connection string without modifying any source code files.

1.  Navigate to **Systems Manager** > **Parameter Store**.
2.  Select the parameter `/cafe/dbUrl`.
3.  Choose **Edit** and replace the **Value** with your new **RDS Endpoint Address**.
4.  **Test:** Refresh the Café website and confirm the **Order History** is accurate.

> 📝 Technical Note: Centralized Configuration
> By using AWS Systems Manager Parameter Store, you achieve "Separation of Concerns." The application only knows the *name* of the parameter, while the DevOps team can update the *value* (the database host) at any time.

## Pro-Tips for Real-World Scenarios

* 💡 **Pro-Tip: Use AWS DMS for Large Migrations:** For databases with gigabytes or terabytes of data, `mysqldump` can be slow and cause downtime. **AWS Database Migration Service (DMS)** allows for "Ongoing Replication," keeping the source and target in sync until you are ready for a near-zero downtime cutover.
* 💡 **Pro-Tip: Secure Configuration:** In production, use **SecureString** parameters in Parameter Store. This allows you to encrypt sensitive data like database passwords using **AWS KMS** (Key Management Service).
* 💡 **Pro-Tip: Monitor FreeableMemory:** Always keep an eye on the `FreeableMemory` metric in CloudWatch. If it drops to zero, the RDS instance will start using "Swap" space on the disk, drastically slowing down your application's response time.

## Useful Commands

| Command | Purpose |
| :--- | :--- |
| `aws rds describe-db-instances` | Retrieves the status and endpoint of your RDS instance. |
| `mysqldump [options] > file.sql` | Creates a logical backup of a local database. |
| `mysql -h [endpoint] -u [user] -p` | Connects to a remote database via the MySQL protocol (Port 3306). |
| `show processlist;` | (SQL Command) Displays active connections to the database, useful for troubleshooting load. |

## Cleanup

1.  **Terminate the RDS Instance:** Select the instance in the console, choose **Delete**, and **uncheck** "Create final snapshot".
2.  **Delete Infrastructure:** Remove the **DB Subnet Group** and the two **Private Subnets**.
3.  **Remove Security Group:** Delete `CafeDatabaseSG` (ensure no resources are still using it).
