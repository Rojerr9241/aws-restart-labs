# Lab 245: Log File Administration

## Objective
Learn to navigate and interpret system logs to monitor security and user activity. This lab focuses on analyzing authentication records and using built-in Linux tools to audit login history.

## Key Concepts
* **System Logs:** Files that record events, errors, and status messages from the OS and applications.
* **Authentication Logs (`secure`):** A specialized log that records all login attempts, both successful and failed, including sudo usage.
* **Log Viewers (`less`):** A terminal utility for viewing large files without loading them into memory entirely, allowing for efficient navigation.
* **Lastlog:** A command that references the `/var/log/lastlog` file to report the most recent login times for all system accounts.

## Task 2: Reviewing Secure Log Files and Login History
Administrators use logs to troubleshoot access issues and investigate security breaches.

### 1. Analyzing Security Records
In this lab, a sample secure log is analyzed using `less`.
* **Command:** `sudo less /tmp/log/secure`
* **Observation:** The log displays timestamps, hostnames, and specific messages like `Failed password for invalid user` or `Authentication failure`.
* **Key Data Points:**
    - **Source IP:** Identifies where the connection attempt originated.
    - **Username:** Shows which account was targeted.
    - **Port:** Indicates the service used (usually SSH on Port 22).

> **📝 Technical Note:** In a standard production environment, the live security log is always located at `/var/log/secure`.

### 2. Auditing User Access
To see a summary of when users last interacted with the system:
* **Command:** `sudo lastlog`
* **Result:** Displays a list of all system users (root, bin, ec2-user, etc.) and their last login date. Users that have never logged in are marked as `**Never logged in**`.

## 💡 Pro-Tips for Log Administration

1. **Live Monitoring:** Use `sudo tail -f /var/log/secure` to watch login attempts in **real-time**. This is extremely useful for active troubleshooting.
2. **Searching in Less:** While inside `less`, press `/` followed by a keyword (e.g., `/Failed`) to jump directly to specific events.
3. **Log Rotation:** Linux uses a service called `logrotate` to compress and archive old logs (e.g., `secure.1.gz`) so they don't consume all your disk space.
4. **The `grep` filter:** You can quickly count failed attempts by combining commands: 
   `sudo grep "Failed" /var/log/secure | wc -l`.

## Command Reference Summary

| Command | Action |
| :--- | :--- |
| `less [file]` | Opens a file for reading with navigation (use `q` to quit). |
| `lastlog` | Displays the most recent login information for all users. |
| `tail -n 20` | Shows the last 20 lines of a log file. |
| `/ [keyword]` | Searches for a specific term while inside the `less` viewer. |
| `grep` | Filters logs to show only lines containing a specific pattern. |
