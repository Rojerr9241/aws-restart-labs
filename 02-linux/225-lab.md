# Lab 225: Introduction to Linux Amazon AMI ✅

## Objective
The primary goal of this lab is to establish a secure remote connection to an Amazon Linux instance and master the use of the built-in documentation system (Manual Pages) to navigate the Linux environment effectively.

## Key Concepts
* **SSH (Secure Shell):** A cryptographic network protocol for operating network services securely over an unsecured network.
* **PEM File:** A privacy-enhanced mail file used for authenticating an SSH session with a key pair instead of a password.
* **Man Pages (Manual Pages):** The standard on-line software documentation found on Unix-like operating systems.
* **chmod (Change Mode):** A Linux command used to manage file and directory permissions.

## Task 1: Secure Connectivity (SSH)

There are two primary methods to connect to your Linux instance depending on your operating system. Both methods use cryptographic key pairs to ensure a secure connection without the need for a traditional password.

### Option A: Windows Users (using PuTTY)
For Windows users, **PuTTY** is the standard tool used to establish a secure shell connection.

1. **Obtain Credentials:** Download the `.ppk` (PuTTY Private Key) file from the Lab Details panel.
2. **Configure PuTTY:**
   - **Host Name:** Enter `ec2-user@<public-ip>`.
   - **Connection Type:** Ensure SSH is selected (Port 22).
   - **Authentication:** In the category tree, navigate to `Connection` > `SSH` > `Auth` > `Credentials` and browse for your `labsuser.ppk` file.
3. **Establish Connection:** Click **Open** and accept the security alert for the initial connection.

### Option B: macOS and Linux Users (Native Terminal)
For users utilizing a native Unix-based terminal.

**Instructions & Workflow:**
1. **Prepare the Key:** Move to the directory where the `labsuser.pem` was downloaded.
2. **Restrict Permissions:** For security reasons, SSH keys must not be accessible by other users.
   ```bash
   chmod 400 labsuser.pem
   ```
> Note: 400 means the owner has read-only access, and no one else has any access.
3. **Connect to the Instance:** Replace <public-ip> with the actual IPv4 address of the EC2.
    ```bash
    ssh -i labsuser.pem ec2-user@<public-ip>
    ```
> Use the identity flag (`-i`) to point to your key.

## Task 2: Exploring Linux Man Pages
In Linux, the command line is self-documented. Mastering the "man pages" is a fundamental skill for any SysOps administrator to understand command syntax and available flags.

**Key Command:**
```bash
man [command_name]
```
Example: `man man` opens the manual about the manual system itself.

### Common Man Page Sections:
| Section | Purpose |
| :--- | :--- |
| **NAME** | The name of the command and a brief one-line description. |
| **SYNOPSIS** | A syntax diagram showing how to run the command with options. |
| **DESCRIPTION** | A detailed explanation of what the command does. |
| **OPTIONS** | Detailed list and explanations of every flag/switch (e.g., `-l`, `-a`). |
| **EXAMPLES** | Practical use cases to understand the command in action. |

> **📝 Technical Note: Navigation**
> While inside a man page:
> - Use **Arrow Keys** or **Spacebar** to scroll.
> - Press **`q`** to quit and return to the terminal prompt.
> - Press **`/`** followed by a word to search for specific terms within the manual.

## 💡 Pro-Tips for Linux Beginners

1. **Permission Denied Error:** If you get an "unprotected private key file" error when trying to SSH, it's because the permissions on your `.pem` file are too open. Always ensure `chmod 400` is applied.
2. **Standard User:** On Amazon Linux AMIs, the default user is `ec2-user`. You do not need a root password to perform administrative tasks; simply prefix commands with `sudo`.
3. **The --help flag:** If a man page feels too dense, many modern commands support the `--help` flag (e.g., `ls --help`) for a quick and concise summary of options.
