# Lab 249: Mastering the Bash Shell ✅

## Objective
Optimize the command-line environment by creating custom shortcuts (aliases) and modifying environment variables. This lab demonstrates how to simplify complex commands and ensure the system can execute custom scripts from any directory.

## Key Concepts
* **Alias:** A custom shortcut for a command or a series of commands. It helps reduce typing and prevents errors in complex syntax.
* **Environment Variables:** Global settings that affect the behavior of the shell session.
* **PATH Variable:** A colon-separated list of directories. When you type a command, the shell searches through these directories in order to find the executable file.
* **Shell Scripts (`.sh`):** Files containing a series of commands that the shell can execute.

## Task 2: Custom Shortcuts with Alias
In this task, we simplified the `tar` backup process by creating a more intuitive command name.

**Command Execution:**
```bash
alias backup='tar -cvzf '
```
* **Why this works:** The alias acts as a prefix. When you `run backup file.tar.gz folder/`, the shell interprets it as `tar -cvzf file.tar.gz folder/`.

* **Flags Recap:**
    * `-c`: Create.
    * `-v`: Verbose (show progress).
    * `-z`: Compress with gzip.
    * `-f`: Output to a file.

> ⚠️ Note: Aliases created this way are temporary and will disappear when the terminal session ends unless added to a configuration file like `.bashrc`.

## Task 3: The PATH Environment Variable
This task explains why some scripts require a full path to run and how to fix "command not found" errors.

**The Execution Challenge**
We attempted to run `hello.sh` in three ways:

1. From inside the directory: `./hello.sh` (Success - path is explicit).
2. From the parent directory: `./bin/hello.sh` (Success - path is explicit).
3. By name only: `hello.sh` (Failed - the directory was not in the system's search list).

The Solution: Updating PATH
To make our custom bin folder accessible from anywhere, we appended it to the existing `$PATH` variable:

```bash
PATH=$PATH:/home/ec2-user/CompanyA/bin
```
**Verification:**
After updating the variable, typing `hello.sh` from any location executes the script correctly because the shell now knows exactly where to look for it.

## 💡 Pro-Tips for Shell Customization

1. **Viewing Active Aliases:** Simply type `alias` without any arguments to see a full list of all shortcuts currently active in your session.
2. **Making Changes Permanent:** Aliases and PATH updates made in the terminal are lost when you log out. To keep them forever, add these commands to your `~/.bashrc` file.
3. **The Power of `$PATH`:** When updating the PATH, always include `$PATH:` at the beginning (e.g., `PATH=$PATH:/new/folder`). If you forget this, you will overwrite the entire variable and lose access to basic commands like `ls` and `cd` for that session!
4. **Script Permissions:** If you receive a "Permission Denied" error when running a script, remember to grant execution rights using `chmod +x script.sh`.
5. **Temporary Unaliasing:** If you have an alias that matches a real command name and you want to run the original command just once, type a backslash before it: `\command`.

## Command Reference Summary

| Command | Action |
| :--- | :--- |
| `alias [name]='[cmd]'` | Creates a temporary shortcut for a long or complex command. |
| `unalias [name]` | Removes a specific alias from the current session. |
| `echo $PATH` | Displays the list of directories where Linux looks for programs. |
| `PATH=$PATH:[dir]` | Appends a new directory to the system search path. |
| `./[script]` | Executes a script located in the current working directory. |
| `cd ..` | Moves up one level to the parent directory. |
