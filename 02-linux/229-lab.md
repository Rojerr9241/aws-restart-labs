# Lab 229: Linux Users and Groups Management

## Objective
Learn to manage a multi-user environment by creating individual accounts, organizing them into functional groups, and understanding the security implications of administrative privileges (sudo).

## Key Concepts
* **User Management:** Creating unique identities for individuals with specific home directories.
* **Group Management:** Logical containers for users to simplify permission management.
* **Primary vs. Secondary Groups:** Every user has a primary group, but they can belong to multiple secondary groups for resource sharing.
* **The Sudoers File:** A security configuration that defines which users or groups can execute commands as the root user.
* **Security Logs:** System files (like `/var/log/secure`) that audit failed authentication and unauthorized sudo attempts.

## Task 4: Testing Permissions and Security Logs
This task demonstrates the boundary between standard users and administrative users (sudoers).

### 1. Switching Users
Use the command `su - <username>` to switch sessions.
* Example: `su arosalez` log in as the Sales Manager.

### 2. Permission Denied Scenario
Standard users cannot write to directories owned by others (like `/home/ec2-user`).
* Attempting `touch myFile.txt` as `arosalez` results in: **Permission denied**.

### 3. Sudo Violation
If a user tries to use `sudo` without being in the sudoers file:
* **Message:** `arosalez is not in the sudoers file. This incident will be reported.`
* **Result:** The system blocks the command and records the attempt.

### 4. Auditing Security
Administrators can check unauthorized attempts by inspecting the secure log:
```bash
sudo cat /var/log/secure
```

Log Entry Example:
```bash
Aug 9 14:45:55 ... sudo: arosalez : user NOT in sudoers ; COMMAND=/bin/touch myFile.txt
```


## 💡 Pro-Tips for User Management

1. **The /etc/passwd File:** This file contains user account information but **not** passwords. Encrypted passwords are stored securely in `/etc/shadow`.
2. **Deleting Users Safely:** Use `sudo userdel -r <username>`. The `-r` flag is vital because it ensures the user's home directory and mail spool are removed along with the account.
3. **Quick Group Check:** Instead of searching through long files, use the `groups <username>` command to instantly see every group a specific user belongs to.
4. **The Security "Incident":** When Linux says "This incident will be reported," it refers to the log entry created in `/var/log/secure`. In a professional environment, these logs are often monitored by security teams.
