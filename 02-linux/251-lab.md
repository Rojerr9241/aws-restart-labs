# Lab 251: Bash Shell Scripting ✅

## Objective
Develop a functional Bash script to automate system administration tasks. This lab focuses on using variables, command substitution, and environmental placeholders to create a dynamic backup utility that organizes files by date and time.

## Key Concepts
* **Shebang (`#!/bin/bash`):** The first line of a script that tells the system which interpreter to use to execute the file.
* **Variables:** Containers for storing data, such as dates or file paths, to make the script reusable and dynamic.
* **Command Substitution (`$()`):** A method to run a command and use its output as a value for a variable.
* **Execution Permissions:** Using `chmod` to transform a text file into a runnable program.

## Task 2: Writing and Executing the Backup Script
Instead of manual backups, we created a script that automatically names files based on the current timestamp.

### 1. Script Preparation
1. **Create the file:** `touch backup.sh`
2. **Grant execution rights:** `chmod 755 backup.sh` (Owner has full access, others can read/execute).

### 2. Script Logic Breakdown
Using `vi`, the following logic was implemented:

```bash
#!/bin/bash
# 1. Capture the current date
DAY="$(date +%Y_%m_%d)"

# 2. Define the destination using the $USER variable
BACKUP="/home/$USER/backups/$DAY-backup-CompanyA.tar.gz"

# 3. Execute the compressed archive command
tar -csvpzf $BACKUP /home/$USER/CompanyA
```

* `$USER`: A system variable that automatically fills in "ec2-user".
* `$DAY`: Injects the timestamp into the filename to prevent overwriting previous backups.

3. Execution and Verification
Running the script with `./backup.sh` initiates the automated process. The success is verified by checking the `backups/` directory:
```bash
ls backups/
# Expected: 2026_05_27-backup-CompanyA.tar.gz
```

## 💡 Pro-Tips for Shell Scripting

1. **Debugging Mode:** If your script behaves unexpectedly, run it with `bash -x backup.sh`. This "xtrace" mode shows you exactly how each command and variable is being processed line-by-line.
2. **Comments for Clarity:** Use the `#` symbol to document your logic. This is a professional standard that helps others understand the purpose of your code.
3. **Quoting Variables:** Always wrap your variables in double quotes (e.g., `"$BACKUP"`) if there is a chance the path contains spaces. This prevents the script from breaking.
4. **Automation with Cron:** To truly automate this, you could add this script to your crontab. For example: `0 2 * * * /home/ec2-user/backup.sh` would run your backup every night at 2:00 AM.
5. **Portable Paths:** Using `$USER` or `$HOME` instead of hardcoding `/home/ec2-user/` makes your script "portable," meaning it will work for any user on any Linux system without modification.
