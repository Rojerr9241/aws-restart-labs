# Lab 239: Linux Administrative Processes and Automation ✅

## Objective
Learn to manage system processes and automate administrative tasks. This lab covers process monitoring using `ps` and `top`, filtering system data with `grep`, and scheduling recurring tasks using `cron` jobs.

## Key Concepts
* **Processes:** Running instances of programs. They can be monitored via `ps` (static snapshot) or `top` (dynamic real-time view).
* **Piping and Filtering:** Using `|` to send output between commands and `grep -v` to exclude specific strings.
* **Cron Daemon:** A time-based job scheduler in Unix-like operating systems.
* **Crontab:** The configuration file that stores the schedule of cron jobs.

## Task 2: Creating a Process Log
Capturing a snapshot of current system activity and filtering it for specific reports.

**Command:**
```bash
sudo ps -aux | grep -v root | sudo tee SharedFolders/processes.csv
```
* `ps -aux`: Lists all running processes for all users.
* `grep -v root`: Inverts the search to exclude any process owned by the root user.
* `tee`: Saves the filtered list into a CSV file while displaying it on the screen.

## Task 3: Real-Time Monitoring with `top`
The `top` command provides a dynamic, real-time view of a running system.

**Key Monitoring Metrics:**

* Tasks: Shows the count of processes in different states (Running, Sleeping, Stopped, Zombie).
* CPU/Memory: Displays utilization percentages for KiB Mem and Swap space.
* Navigation: Press `q` to exit the interface.

## Task 4: Automating Tasks with Cron Jobs
Scheduling a script to create a filtered audit file of all `.csv` documents every hour.

**Crontab Configuration (`sudo crontab -e`):**
To ensure the job runs correctly, environment variables (SHELL and PATH) are defined before the schedule.

**The Scheduled Job:**
```bash
0 * * * * ls -la $(find .) | sed -e 's/..csv/#####.csv/g' > /home/ec2-user/companyA/SharedFolders/filteredAudit.csv
```

### Understanding the Cron Schedule (`0 * * * *`)
The crontab uses a five-field time format followed by the command to execute:

| Minute | Hour | Day of Month | Month | Day of Week | Command |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `0` | `*` | `*` | `*` | `*` | `ls -la $(find .) ...` |

*This specific configuration executes the audit script at **minute 0 of every hour**, every day of the year.*

## 💡 Pro-Tips for Process Management

1. **Identifying Resource Hogs:** While inside the `top` interface, you can press **`M`** to sort processes by Memory usage or **`P`** to sort by CPU usage.
2. **The "Zombie" State:** A zombie process is one that has finished execution but remains in the process table. While they don't consume many resources, a high number of zombies can indicate a bug in a parent process.
3. **Crontab Safety:** Always use `sudo crontab -l` (list) to check your existing jobs before using `sudo crontab -e` (edit) to prevent accidental deletions.
4. **Kill Commands:** If a process becomes unresponsive, use `sudo kill [PID]` to stop it gracefully. Use `sudo kill -9 [PID]` only as a last resort to force-stop a process.

## Command Reference Summary

| Command | Action |
| :--- | :--- |
| `ps -aux` | Displays a static snapshot of all running processes. |
| `top` | Opens a dynamic, real-time system monitor. |
| `grep -v [string]` | Filters output to **exclude** lines containing the string. |
| `crontab -e` | Opens the cron schedule editor. |
| `crontab -l` | Lists all currently installed cron jobs. |
| `sed` | Stream Editor used for text transformation (e.g., masking filenames). |
