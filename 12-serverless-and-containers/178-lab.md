## Objective
The objective of this lab is to design and deploy a serverless sales reporting solution. You will implement a decoupled architecture where a scheduled CloudWatch Event triggers a master Lambda function, which in turn invokes a data-extraction function. The solution involves managing external Python libraries via Lambda Layers, handling cross-function permissions, and troubleshooting VPC connectivity to an RDS/EC2 database.

## Key Concepts

* **AWS Lambda:** A serverless, event-driven compute service that lets you run code without provisioning or managing servers.
* **Lambda Layers:** A distribution mechanism for libraries, custom runtimes, and other function dependencies. It allows you to keep deployment packages small and share code across multiple functions.
* **Event-Driven Invocation:** The process of triggering a function based on a schedule (Cron) or an event from another AWS service.
* **Statelessness:** Lambda functions are stateless; they only exist during the execution time. Configuration data must be fetched from external sources like **Systems Manager Parameter Store**.
* **VPC Lambda Connectivity:** By default, Lambda runs in an AWS-managed VPC. To access a database on an EC2 instance or RDS in your private network, the function must be configured with a VPC Endpoint (ENI).

## Step-by-Step Instructions

### 1. IAM Permissions Audit
Before deployment, verify that the service roles have the necessary trust relationships and policies.

* **salesAnalysisReportRole:** Requires `lambda.amazonaws.com` as a trusted entity and policies for SNS (Publish), SSM (Read), and Lambda (Invoke).
* **salesAnalysisReportDERole:** Requires VPC execution permissions (`AWSLambdaVPCAccessRunRole`) to manage network interfaces within the private subnet.

### 2. Implementing Lambda Layers and the Data Extractor
Satisfy external dependencies (PyMySQL) and create the worker function.

1.  **Create Layer:** Name it `pymysqlLibrary`. Upload `pymysql-v3.zip` and select **Python 3.9** as the compatible runtime.
2.  **Create Data Extractor:**
    * **Name:** `salesAnalysisReportDataExtractor`.
    * **Role:** `salesAnalysisReportDERole`.
    * **Layer:** Attach the `pymysqlLibrary` created earlier.
3.  **VPC Configuration:** Attach the function to the `Cafe VPC`, `Public Subnet 1`, and `CafeSecurityGroup`.

> 📝 Technical Note: Layer Folder Structure
> For Python, Lambda layers must follow a specific path: `python/lib/python3.x/site-packages/` or simply `python/`. If the library is not in the correct subfolder within the ZIP, the function will fail with an `ImportError`.

### 3. Troubleshooting Connectivity
Initially, the `DataExtractor` function will fail due to a timeout.

1.  **Diagnosis:** The function attempts to connect to port 3306 on the EC2 instance, but the **CafeSecurityGroup** only allows HTTP/SSH.
2.  **Fix:** Add an **Inbound Rule** to the `CafeSecurityGroup`:
    * **Type:** MySQL/Aurora (3306).
    * **Source:** Reference the `CafeSecurityGroup` itself (Self-reference) or the specific subnet CIDR.

### 4. Deploying the Master Function (CLI)
Use the AWS CLI to deploy the reporting logic.

```bash
aws lambda create-function \
--function-name salesAnalysisReport \
--runtime python3.9 \
--zip-file fileb://salesAnalysisReport-v2.zip \
--handler salesAnalysisReport.lambda_handler \
--region us-west-2 \
--role <salesAnalysisReportRoleARN>
```

1. **Environment Variables:** Add topicARN with the value of your SNS topic.
2. **Trigger:** Add an EventBridge (CloudWatch Events) trigger with a Schedule Expression:

    * **Production Cron:** `cron(0 20 ? * MON-SAT *) (8 PM UTC)`.

*Command explanation*: `fileb://` is used in the CLI to indicate that the file should be read as a binary. This is mandatory when uploading ZIP deployment packages.

## Infrastructure as Code: Function Analysis

In a serverless architecture, functions often act as microservices that collaborate to complete a task. Below is a fragment of the **Master Function** logic, demonstrating how it orchestrates the process by invoking the secondary "Worker" function and publishing the results.

📂 **Source Code Reference:** [salesAnalysisReport.py](./assets/lambda/salesAnalysisReport.py)

```python
# Fragment: Orchestration Logic
# 1. Invoking the Data Extractor Function synchronously
response = lambda_client.invoke(
    FunctionName='salesAnalysisReportDataExtractor',
    InvocationType='RequestResponse', 
    Payload=json.dumps(db_credentials)
)

# 2. Processing the payload and sending via SNS
report_data = json.loads(response['Payload'].read())
sns_client.publish(
    TopicArn=os.environ['topicARN'],
    Message=format_report(report_data),
    Subject='Daily Sales Analysis Report'
)
```

## Pro-Tips for Real-World Scenarios

* **💡 Pro-Tip: Lambda Timeouts:** The default timeout is 3 seconds. For database queries or complex reporting, always increase this to at least 30 seconds to avoid Task timed out errors during high-load periods.

* **💡 Pro-Tip: Use Secrets Manager over Parameter Store:** While Parameter Store is great for config, AWS Secrets Manager is better for database passwords as it offers built-in password rotation and tighter integration with RDS.

* **💡 Pro-Tip: Avoid VPC for Lambda unless necessary:** Attaching a function to a VPC adds cold-start latency due to ENI provisioning. Only do it if you need to reach private resources like RDS or internal APIs.
