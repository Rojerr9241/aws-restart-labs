# Lab Challenge: AWS Lambda Word Count Execution

## Challenge Architecture
This lab implements an **Event-Driven Architecture**. When a file is uploaded to **Amazon S3**, it triggers an **AWS Lambda** function that processes the text, counts the words, and sends the results via **Amazon SNS** to an email subscriber.

---

## Task 1: Create the Amazon SNS Topic
The Lambda function requires a communication channel to report the results.

1.  Navigate to **SNS** > **Topics** > **Create topic**.
2.  **Type:** Select **Standard**.
3.  **Name:** `WordCountTopic`.
4.  Choose **Create topic**.
5.  **Important:** Copy the **Topic ARN** (e.g., `arn:aws:sns:us-west-2:123456789012:WordCountTopic`). You will need this for the Lambda environment variables.
6.  **Subscription:**
    * Choose **Create subscription**.
    * **Protocol:** `Email`.
    * **Endpoint:** Enter your personal email address.
    * Choose **Create subscription**.
    * **Action Required:** Check your email inbox and click **Confirm Subscription** in the email sent by AWS.

## Task 2: Create the S3 Source Bucket
This bucket acts as the event trigger for the Lambda function.

1.  Navigate to **S3** > **Create bucket**.
2.  **Bucket name:** `word-count-input-[your-initials]-[random-numbers]`.
3.  **Region:** Ensure it is the same Region used for the SNS topic.
4.  Choose **Create bucket**.

## Task 3: Create and Configure the Lambda Function
The Lambda function contains the Python logic to count words and publish the result.

1.  Navigate to **Lambda** > **Create function**.
2.  **Option:** Author from scratch.
3.  **Function name:** `WordCountFunction`.
4.  **Runtime:** `Python 3.x`.
5.  **Permissions:** Expand "Change default execution role":
    * Select **Use an existing role**.
    * Choose **`LambdaAccessRole`**.
6.  Choose **Create function**.

### 3.1 Function Code
In the **Code** tab, replace the boilerplate code with the following:

```python
import json
import boto3
import urllib.parse
import os

s3 = boto3.client('s3')
sns = boto3.client('sns')

def lambda_handler(event, context):
    try:
        # Get bucket and file name from the S3 event
        bucket_name = event['Records'][0]['s3']['bucket']['name']
        object_key = urllib.parse.unquote_plus(event['Records'][0]['s3']['object']['key'])

        # Retrieve file content from S3
        response = s3.get_object(Bucket=bucket_name, Key=object_key)
        file_content = response['Body'].read().decode('utf-8')

        # Logic: Split text into words and count
        words = file_content.split()
        word_count = len(words)

        # Format message as per challenge requirements
        message = f"The word count in the {object_key} file is {word_count}."
        
        # Get Topic ARN from Environment Variables
        topic_arn = os.environ['TOPIC_ARN']

        # Publish result to SNS
        sns.publish(
            TopicArn=topic_arn,
            Subject='Word Count Result',
            Message=message
        )

        return {
            'statusCode': 200,
            'body': json.dumps(message)
        }

    except Exception as e:
        print(e)
        return {
            'statusCode': 500,
            'body': json.dumps(str(e))
        }
```
* Choose Deploy.

### 3.2 Environment Variables
Para mantener el código flexible y seguro, almacenamos el ARN del tópico SNS fuera del script. De esta manera, si el tópico cambia, no es necesario editar el código de la función.

1.  Ve a la pestaña **Configuration** y selecciona **Environment variables** en el menú lateral izquierdo.
2.  Haz clic en **Edit** y luego en **Add environment variable**.
3.  Configura los siguientes valores:
    * **Key:** `TOPIC_ARN`
    * **Value:** [Pega aquí el **ARN del Tópico SNS** que copiaste en la Tarea 1]
4.  Haz clic en **Save**.


## Task 4: Configure the S3 Trigger
Para que la arquitectura sea orientada a eventos, debemos conectar S3 con Lambda para que la función se ejecute automáticamente al detectar un nuevo archivo.

1.  En la sección **Function overview** de tu función Lambda, haz clic en **Add trigger**.
2.  Selecciona **S3** de la lista desplegable.
3.  **Bucket:** Selecciona el bucket creado en la Tarea 2.
4.  **Event type:** Asegúrate de que esté seleccionado `All object create events`.
5.  Marca la casilla de confirmación de **Recursive invocation** (Aviso de invocación recursiva).
6.  Haz clic en **Add**.

## 💡 Expert Pro-Tips

* **Eficiencia Serverless:** Esta solución es 100% "serverless". No pagas por servidores inactivos; AWS solo factura por el tiempo de ejecución (milisegundos) de la función Lambda cuando se sube un archivo.
* **Decodificación de Keys:** El uso de `urllib.parse.unquote_plus` en el código es vital. S3 reemplaza los espacios en los nombres de archivo por el símbolo `+` en los metadatos del evento. Esta función los decodifica para que Lambda encuentre el archivo correctamente.
* **Logs y Monitoreo:** Si no recibes el correo, revisa la pestaña **Monitor** > **CloudWatch Logs** en Lambda. Allí podrás ver si hubo errores de permisos o si el ARN del SNS estaba mal configurado.
* **Escalabilidad:** Esta misma función puede procesar miles de archivos subidos simultáneamente de forma automática, escalando sin necesidad de intervención manual.
