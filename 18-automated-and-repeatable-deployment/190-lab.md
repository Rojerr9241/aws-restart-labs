# Lab 190: Automation with CloudFormation
**Course:** AWS re/Start | **Module:** Automated and Repeatable Deployment

## Objective
The objective of this lab is to master the basics of Infrastructure as Code (IaC) using AWS CloudFormation. You will deploy a foundational network, perform stack updates to add storage (S3) and compute (EC2) resources, and learn how CloudFormation manages resource dependencies and automated cleanups.

## Key Concepts

* **Infrastructure as Code (IaC):** The practice of managing and provisioning technology stacks through machine-readable definition files (YAML or JSON) rather than manual hardware configuration or interactive tools.
* **CloudFormation Stack:** A single unit of management. When you create, update, or delete a stack, CloudFormation ensures all resources defined in the template are managed accordingly.
* **Parameters:** Enable templates to be dynamic by prompting users for input (e.g., CIDR blocks or Instance Types) during deployment.
* **Resources:** The heart of the template; this section declares the specific AWS components you want to provision (VPC, EC2, S3, etc.).
* **Logical ID vs. Physical ID:** In the template, you give a resource a "Logical ID" (e.g., `MyS3Bucket`). Once deployed, AWS assigns it a "Physical ID" (e.g., `lab-mys3bucket-abc123xyz`).
* **Intrinsic Functions (!Ref):** Used to assign values to properties from other resources or parameters within the same template.

## Step-by-Step Instructions

### 1. Initial Stack Deployment
Provision a VPC and Security Group using a pre-defined YAML template.

1.  Download `task1.yaml`.
2.  Navigate to the **CloudFormation** console and select **Create stack** (with new resources).
3.  Upload the template file and name the stack `Lab`.
4.  Monitor the **Events** tab to see the sequence of resource creation.

> 📝 Technical Note: Creation Order
> CloudFormation is "dependency-aware." It knows it must create the VPC before it can create the Subnet or the Security Group, even if they are listed in a different order in the template.

### 2. Extending Infrastructure (Adding S3)
Modify the template to add a storage layer.

1.  Open `task1.yaml` in VS Code.
2.  Under the `Resources:` section, add the following two lines:
    ```yaml
    MyS3Bucket:
      Type: AWS::S3::Bucket
    ```
3.  In the CloudFormation console, select the `Lab` stack and choose **Update**.
4.  Upload your modified file and observe the **Change Set** (it should show "Add" for the S3 bucket).

> 💡 Pro-Tip: YAML Indentation
> YAML is strictly space-sensitive. Always use exactly **two spaces** per indentation level. Using tabs or inconsistent spacing will result in a template validation error.

### 3. Advanced Resource Definition (EC2 & SSM)
Add a compute instance that dynamically fetches the latest AMI ID.

1.  **Add Parameter:** Under `Parameters:`, add code to fetch the latest Amazon Linux 2 AMI via Systems Manager:
    ```yaml
    AmazonLinuxAMIID:
      Type: AWS::SSM::Parameter::Value<AWS::EC2::Image::Id>
      Default: /aws/service/ami-amazon-linux-latest/amzn2-ami-hvm-x86_64-gp2
    ```
2.  **Add EC2 Resource:** Under `Resources:`, define the instance and link it to the existing network:
    ```yaml
    AppServer:
      Type: AWS::EC2::Instance
      Properties:
        ImageId: !Ref AmazonLinuxAMIID
        InstanceType: t3.micro
        SecurityGroupIds:
          - !Ref AppSecurityGroup
        SubnetId: !Ref PublicSubnet
        Tags:
          - Key: Name
            Value: App Server
    ```
3.  Perform another **Stack Update** with the revised file.

> **Command explanation:** `!Ref AmazonLinuxAMIID` tells CloudFormation to use the value retrieved from the Systems Manager Parameter Store. This ensures your template always uses a patched, up-to-date image without you having to manually update the AMI ID.

### 4. Stack Termination
Cleanup all lab resources.

1.  Select the `Lab` stack.
2.  Click **Delete** -> **Delete stack**.

> ⚠️ Security Note: S3 Bucket Deletion
> By default, CloudFormation will fail to delete a stack if it contains an S3 bucket that is **not empty**. You must either empty the bucket manually before deleting the stack or set a `DeletionPolicy: Retain` if you wish to keep the data.

## Pro-Tips for Real-World Scenarios

* 💡 **Pro-Tip: Use Change Sets:** In production, always review the **Change Set** before applying an update. It tells you if a resource will be "Modified" (no downtime), "Replaced" (new Physical ID, potential downtime), or "Deleted."
* 💡 **Pro-Tip: CloudFormation Linter:** Install the "CloudFormation Linter" extension in VS Code. It will highlight syntax and logic errors in your YAML files before you even attempt to upload them to AWS.
* 💡 **Pro-Tip: Modular Templates:** For large projects, don't put everything in one file. Use **Nested Stacks** to separate your Network (VPC/Subnets) from your Application (EC2/RDS) and Security (IAM/SGs).

## Useful Commands / Reference

| Keyword | Purpose |
| :--- | :--- |
| `!Ref` | Returns the value of the specified parameter or resource. |
| `!GetAtt` | Returns the value of an attribute from a resource (e.g., an S3 Bucket's ARN). |
| `CREATE_COMPLETE` | Indicates the resource and stack were successfully provisioned. |
| `ROLLBACK_IN_PROGRESS` | Triggered if an error occurs. CloudFormation will attempt to delete everything it just created to leave the account clean. |

## Cleanup
Cleanup all lab resources.

1.  Select the `Lab` stack.
2.  Click **Delete** -> **Delete stack**. All resources (EC2, S3, VPC) are removed automatically.

> ⚠️ Security Note: S3 Bucket Deletion
> By default, CloudFormation will fail to delete a stack if it contains an S3 bucket that is **not empty**. You must either empty the bucket manually before deleting the stack or set a `DeletionPolicy: Retain` if you wish to keep the data.

### Highlight: Dynamic Compute Layer
The following fragment demonstrates how the template uses the **SSM Parameter Store** to fetch the latest AMI and the `!Ref` function to link the instance to the network resources defined earlier in the stack:

```yaml
  # Compute Layer: Dynamic EC2 Instance
  AppServer:
    Type: AWS::EC2::Instance
    Properties:
      ImageId: !Ref AmazonLinuxAMIID     # Fetches latest AMI ID dynamically
      InstanceType: t3.micro
      SecurityGroupIds:
        - !Ref AppSecurityGroup          # Links to the Security Group logical ID
      SubnetId: !Ref PublicSubnet         # Links to the Subnet logical ID
      Tags:
        - Key: Name
          Value: App Server
